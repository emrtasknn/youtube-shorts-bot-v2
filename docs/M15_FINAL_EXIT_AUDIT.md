# M15 Final Exit Audit — Autonomous Audio Intelligence

Status: **PASS / COMPLETE**

## Scope

M15 upgrades the production Short pipeline to one autonomous, token-conscious audio mix per run.

Default path:
- one script generation call
- zero additional LLM calls for audio planning
- one TTS generation
- one deterministic music selection
- bounded SFX selection
- one audio mix
- one FFmpeg render
- one audio QC pass
- at most one bounded repair render

No two-variant audio generation is performed by default.

## M15.1 — Voice Direction + TTS Hardening

Implemented:
- deterministic AudioDirector
- narration normalization
- sentence-boundary insertion
- compact hook emphasis metadata
- energy classification
- existing TTS provider abstraction preserved
- final rendered audio is subject to M15 QC

No extra LLM call is introduced.

## M15.2 — Music Intelligence

Implemented:
- deterministic MusicCatalog
- mood/energy/BPM/instrumental metadata
- topic-aware selection
- traceable source/license metadata
- original procedural instrumental tracks

The production implementation deliberately uses original procedural audio rather than an external copyrighted catalog. This avoids requiring an external music API or silently assuming a third-party license.

The catalog does not claim that any track is inherently viral. It selects an audio profile intended to support retention-oriented pacing.

## M15.3 — SFX Intelligence

Implemented:
- deterministic semantic trigger matching
- bounded maximum of two SFX cues
- impact/whoosh/alarm/heartbeat cue families
- original procedural SFX generation
- deterministic placement in the background bed
- traceable SFX metadata

Low-confidence/no-match cases produce no SFX.

## M15.4 — Dynamic Audio Mixer

Implemented by reusing the existing FFmpeg audio pipeline:
- voice remains the priority signal
- background bed is sidechain-ducked under narration
- configurable threshold/ratio/attack/release
- music has deterministic fade envelope
- SFX have decaying envelopes and bounded density
- one combined background bed is passed to the renderer

This avoids rebuilding the existing reliable FFmpeg renderer.

## M15.5 — Audio QC + Autonomous Repair

Implemented:
- FFmpeg volumedetect
- FFmpeg silencedetect
- peak threshold
- mean-volume range
- silence-ratio threshold
- hard QC gate before Telegram approval
- exactly one bounded repair attempt
- repair reduces background volume and strengthens ducking
- second failure terminates generation rather than looping indefinitely

## M15.6 — Production Measurement

Implemented without a new migration:
- StageExecutionModel persists the M15 audio profile and QC metadata
- stored fields include music identity, mood, BPM, license/source, SFX identity, voice provider, energy, emphasis terms, QC metrics and repair status
- metadata is linked to run_id, so it can be joined to existing experiment/optimization/performance data

This is sufficient for M12/M13 controlled audio experiments without generating A/B audio variants by default.

## Copyright / licensing posture

M15's default audio is original procedural audio generated by the application and tagged original-procedural. It does not download third-party music or SFX and therefore does not depend on an unverified royalty-free claim.

For future external music catalogs, source URL, license, attribution requirements and commercial-use eligibility must be persisted before a track is allowed into production.
